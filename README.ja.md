# herdr-second-opinion

**作業中のセッションを離れずに、別のコーディングエージェントからセカンドオピニオンをもらう。** 隣のペインで様子を見ながら口を挟めて、採用した指摘だけを元のエージェントに返せます。

[English](README.md) | [日本語](README.ja.md)

[herdr](https://github.com/herdrdev/herdr) のプラグインです。Claude Code（または Codex）と作業しているときに、もう一方のエージェントに計画や diff を見てほしくなることがあります。普通はペイン間で文章をコピーし、待って、答えを貼り戻す必要がありますが、このプラグインはその往復を代わりに行います。

1. **作業中のエージェントでキーを押し**、レビューしてもらう対象を選びます。直近の出力（計画や回答）、未コミットの diff、またはその両方です。「競合状態を重点的に」のようなメモも添えられます。
2. **右側にもう一方のエージェントが開き**、レビューします。普通のペインなので、いつでも様子を見たり話しかけたりできます。
3. **指摘を選ぶ画面がポップアップで開きます。** 指摘ごとに、重要度・根拠（`ファイル:行`）・提案が並びます。同意するものにチェックを付けるほか、`f` で追加の質問、`d` で破棄ができます。
4. **Enter を押すと**、採用した指摘とメモだけが元のエージェントに届きます。見送った指摘も伝えるので、そこには手を付けません。

## インストール

```sh
herdr plugin install maromocooo/herdr-second-opinion
```

`~/.config/herdr/config.toml` でキーを割り当て、`herdr server reload-config` を実行します。

```toml
[[keys.command]]
key = "prefix+o"
type = "plugin_action"
command = "second-opinion.ask"
```

必要なもの:
- herdr 0.9.5 以上、Node 20 以上
- Claude Code と Codex CLI（どちらもインストール済みでログイン済み）。Claude には Codex が、Codex には Claude がレビュー役として付きます。

## 仕組み

- **いつものエージェントをそのまま使う。** レビュー役は herdr の `agent start` で起動するので、普段のログインや設定がそのまま使われます。API キーは不要です。
- **文脈が続く。** 同じセッションの次のレビューでは、レビュー役のペインを使い回します。追加の質問も、前の文脈を踏まえて答えます。
- **画面の読み取りではなくファイルでやり取りする。** 依頼は `.second-opinion/<run>/context.md` に書き、レビュー役は `findings-N.json` に書きます。どちらもレビュー役が読み書きできるようにリポジトリ内に置き、`.git/info/exclude` で git の対象外にします。指摘は表示する前に内容を検証します。
- **レビューだけを頼む。** レビュー役には、プロジェクトのファイルを編集しないよう指示します。ただし中身は普段と同じ権限で動く通常のエージェントなので、気になる場合はペインを見ていてください。
- **判断はあなたが行う。** レビュー役が質問や承認待ちで止まったら、通知が届きます。答えるのはあなたで、プラグインが代わりに答えることはありません。
- **作業の邪魔をしない。** 元のエージェントが作業中なら、終わるのを待ってから送ります。
- **見送った指摘は繰り返さない。** 同じセッションの次のレビューに、見送った指摘を伝えます。レビュー役がまた挙げるのは、理由があるときだけです。

## データの送り先

レビュー役が読むのは次の内容です。
- 元のエージェントのターミナルの直近の出力（ステータスラインが含まれることがあります）
- 未コミットの diff（選んだ場合）
- あなたのメモ

自分でそのエージェントに貼り付けるのと同じく、レビュー役の CLI のモデル提供元に送られます。ターミナルの出力を含めたくない場合は「diff」を選んでください。

## 制約（v0.1）

- 対応は Claude Code ↔ Codex のみです。他のエージェントから呼ぶこともでき、その場合のレビュー役は Codex です。
- レビュー役は1人で、1回のレビューと追加の質問だけです。投票や複数エージェントでの合議はしません。
- 動作確認は macOS と herdr 0.9.5 で行いました。Linux でも動くはずです。
- herdr の PATH にある `node` が壊れている環境では、ログインシェル経由で起動するため、ポップアップの表示に数秒かかります。
